# 課題0504 リバースエンジニアリング

`original.c` は，ある仕様で動く，誰かが書いたプログラムである．**仕様は書かれていない．** 変数名も条件も読みにくい．

## 課題
1. `original.c` をコンパイルして実行し，**どんな入力で OK，どんな入力で NG** になるか調べよ．
2. -5 から 20 までの整数のうち，**OK になる整数を全部** `spec.txt` に書け(空白または改行区切り)．
3. **動作を変えずに** 読みやすく書き直したものを `main.c` に書け(`main.c` の初期状態は `original.c` と同じ)．
   - 意味の分かる変数名にする(**1文字の変数名は禁止**)
   - コメントを2つ以上つける(仕様を日本語で説明する)
   - OK/NG の判定は -5〜20 以外の入力でも `original.c` と同じであること

ヒント: `!(A || B || C)` は「A でも B でも C でもない」という意味である(ド・モルガンの法則)．

## 提出するファイル
- `main.c` : 書き直したプログラム
- `spec.txt` : OKになる整数の一覧
- `ai_log.txt`
- `original.c` : 読み解く対象(**変更しない**)

## 採点について
- push すると GitHub Actions が自動採点します。結果は Actions のログと、フィードバック用の Pull Request に出ます。
- 採点は **プログラムを実行した結果** で行います。何度でも push して再採点できます。
- `ai_log.txt`(AI利用ログ)も採点対象です(10点)。AIを使ってもかまいません。ただし **AIの答えを自分で確かめること** が課題の目的です。
